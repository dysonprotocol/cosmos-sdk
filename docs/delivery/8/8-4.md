# 8-4 Implement `nftStore.js` Alpine store

[Back to task list](./tasks.md) | [View Backlog](../backlog.md#user-content-8)

## Analysis
- **Purpose:** Provide an Alpine store (`nftStore`) responsible for fetching NFT classes and NFTs, and handling bidding and listing actions client-side.
- **Non-functional Considerations:** Keep payloads minimal; ensure idempotent actions; maintain accessibility by dispatching custom events for UI feedback.

## Design
- **Technical Specifications:**
  - File: `demo-dwapp/static/js/nftStore.js` exports Alpine store.
  - Methods:
    * `fetchClasses()` → GET `/nftclasses` (populates `classes`).
    * `fetchNFTs(filter)` → GET `/nfts/...` (populates `nfts`).
    * `placeBid(classId, nftId, denom, amount)`.
    * `acceptBid(bidId)` / `rejectBid(bidId)`.
    * `toggleListed(nftId, listed)` respecting `nftclass.always_listed` precedence.
  - State is reactive via Alpine `store` API.
  - HTTP layer uses `fetch` with centralised `handleError` returning JSON.

## Testing
- **Test Cases:**
  1. Calling `fetchClasses()` populates `classes` with expected length.
  2. `placeBid` with valid denom returns HTTP 200 and updates reactive state.
  3. `placeBid` with disallowed denom bubbles error event.
  4. `toggleListed` updates UI checkbox and persists backend state.

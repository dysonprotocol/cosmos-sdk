# 18-2 Add QueryMetrics RPC to query.proto and implement endpoint

[Back to task list](./18-tasks.md) | [View Backlog](../backlog.md#user-content-18)

## Analysis

- **Purpose:** Create a new gRPC endpoint that allows querying storage metrics for a specific owner address, providing visibility into total bytes consumed.
- **Non-functional Considerations:**
  - Security: Only allow reading metrics, no modification capabilities
  - Performance: Efficient single-address lookup with minimal database queries
  - Observability: Endpoint should be accessible via both gRPC and REST API
- **Business Rules:**
  - Query accepts owner address parameter and returns metrics for that address only
  - Returns zero bytes if no storage entries exist for the address
  - Must handle invalid addresses gracefully with proper error responses

## Design

- **Technical Specifications:**
  - Add `QueryMetrics` RPC method to Query service in `query.proto`
  - Create `QueryMetricsRequest` with owner field (cosmos address)
  - Create `QueryMetricsResponse` with StorageMetrics field
  - Implement handler in `grpc_query.go`
- **Architectural Compliance:**
  - Follows existing query pattern used by StorageGet and StorageList
  - Uses proper HTTP annotations for REST API exposure
  - Maintains consistency with existing keeper query methods

## Testing

- **Test Cases:**
  - Valid address returns correct metrics
  - Invalid address returns appropriate error
  - Non-existent address returns zero bytes
  - gRPC and REST endpoints both function correctly
- **Test Data Requirements:**
  - Multiple test addresses with varying storage usage
  - Invalid address formats for error testing

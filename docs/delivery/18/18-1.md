# 18-1 Add StorageMetrics message to storage.proto

[Back to task list](./18-tasks.md) | [View Backlog](../backlog.md#user-content-18)

## Analysis

- **Purpose:** Define a new protobuf message to track storage usage metrics per owner address, enabling monitoring of total bytes consumed in the storage module.
- **Non-functional Considerations:**
  - Security: Metrics data should only be readable, not directly modifiable by users
  - Performance: Lightweight message structure to minimise impact on queries
  - Observability: Metrics will be used for system monitoring and potentially billing
- **Business Rules:**
  - Each owner address has exactly one StorageMetrics entry
  - Total bytes must accurately reflect sum of all storage entry data sizes for that owner
  - Metrics must be queryable but not directly updatable via transactions

## Design

- **Technical Specifications:**
  - Add `StorageMetrics` message to `proto/dysonprotocol/storage/v1/storage.proto`
  - Message fields: `owner` (string, cosmos address), `total_bytes` (uint64)
  - Follow existing protobuf conventions and annotations used in Storage message
- **Architectural Compliance:**
  - Follows Cosmos SDK protobuf patterns with proper annotations
  - Uses cosmos_proto.scalar for address validation
  - Maintains consistency with existing storage module message structure

## Testing

- **Test Cases:**
  - Protobuf compilation succeeds without errors
  - Generated Go code includes proper field types and validation
  - Message can be serialised and deserialised correctly
- **Test Data Requirements:**
  - Sample StorageMetrics messages with various owner addresses and byte counts

## Change Plan

- **Files to Modify:**
  - `proto/dysonprotocol/storage/v1/storage.proto`
- **Implementation Approach:**

  - Include proper protobuf field annotations consistent with Storage message

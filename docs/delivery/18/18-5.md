# 18-5 Update CLI and add tests for QueryMetrics functionality

[Back to task list](./18-tasks.md) | [View Backlog](../backlog.md#user-content-18)

## Analysis

- **Purpose:** Add CLI command for querying storage metrics and create comprehensive tests to verify the complete QueryMetrics functionality works correctly.
- **Non-functional Considerations:**
  - Security: CLI must validate address formats before querying
  - Performance: Tests should cover various data sizes and scenarios efficiently
  - Observability: Clear CLI output and comprehensive test coverage for debugging
- **Business Rules:**
  - CLI accepts owner address parameter and displays metrics in readable format
  - Tests must verify end-to-end functionality from storage operations to metrics queries
  - Test coverage must include edge cases and error conditions
  - Tests must be integrated into existing test suite structure

## Testing

- **Test Cases:**
  - CLI command accepts valid addresses and returns formatted metrics
  - CLI command handles invalid addresses with appropriate errors
  - Integration tests verify metrics accuracy after storage operations
  - Edge cases: empty storage, large data sizes, multiple operations
  - Error scenarios: invalid addresses, network failures
- **Test Data Requirements:**
  - Multiple test addresses with varying storage patterns
  - Large and small data entries for metrics calculation verification
  - Invalid address formats for error testing

## Design

- **Technical Specifications:**
  - Add `query storage-metrics` CLI command in query.go
  - Create comprehensive test suite in tests/storage/
  - Include unit tests for keeper methods and integration tests for full workflow
  - Follow existing CLI command patterns and test structure
- **Architectural Compliance:**
  - Uses existing CLI framework and patterns from storage module
  - Integrates with existing test infrastructure
  - Maintains consistency with other query commands

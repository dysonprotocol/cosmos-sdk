# 19-3 Implement staking module integration for delegation queries

[Back to task list](./19-tasks.md) | [View Backlog](../backlog.md#user-content-19)

## Analysis
- **Purpose:** Integrate with cosmos-sdk staking module to query total delegated stake for any address.
- **Non-functional Considerations:**
  - Security: Must properly validate delegator addresses and handle query failures
  - Performance: Staking queries may be expensive, should be used judiciously
  - Observability: Query failures should be logged and bubbled up appropriately
- **Business Rules:**
  - Sum all delegated amounts for the given address across all validators
  - Include all delegation states (bonded, unbonding, redelegating)
  - Return total amount in udys as cosmos-sdk math.Int
  - Handle case where address has no delegations (return zero)
  - Propagate staking module query errors without obscuring them

## Design
- **Technical Specifications:**
  - Add `GetTotalDelegatedStake(ctx context.Context, delegatorAddr string) (math.Int, error)` method to Keeper
  - Use cosmos-sdk staking module's `DelegatorDelegations` query
  - Sum all `balance.amount` fields from delegation responses
  - Ensure proper error handling for invalid addresses and query failures
  - Add staking module keeper to storage keeper dependencies
- **Architectural Compliance:**
  - Follows cosmos-sdk patterns for inter-module communication
  - Uses proper context propagation for queries
  - Maintains separation of concerns between storage and staking logic

## Testing
- **Test Cases:**
  - Successfully query delegations for address with stake
  - Handle address with no delegations (return zero)
  - Handle invalid delegator address format
  - Handle staking module query failures
  - Verify correct sum calculation for multiple delegations
  - Edge case: delegations with zero amounts
- **Test Data Requirements:**
  - Valid bech32 delegator addresses
  - Mock delegation responses with various amounts
  - Invalid address formats for error testing

## Change Plan
- **Files to Modify:**
  - `x/storage/keeper/keeper.go` - Add staking keeper dependency and GetTotalDelegatedStake method
  - `x/storage/module.go` - Update keeper constructor to include staking keeper
  - `app.go` - Ensure staking keeper is passed to storage keeper initialization
- **Implementation Approach:**
  1. Add stakingkeeper.Keeper field to storage Keeper struct
  2. Update NewKeeper constructor to accept and store staking keeper
  3. Implement GetTotalDelegatedStake method using staking.DelegatorDelegations query
  4. Add proper error handling and validation
  5. Update app.go to pass staking keeper during module initialization
  6. Add comprehensive unit tests with mocked staking keeper

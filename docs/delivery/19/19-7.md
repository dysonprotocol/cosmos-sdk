# 19-7 Update StorageDelete to recalculate min_stake_amount without blocking

[Back to task list](./19-tasks.md) | [View Backlog](../backlog.md#user-content-19)

## Analysis
- **Purpose:** Ensure StorageDelete operations update min_stake_amount in metrics while never blocking deletion due to insufficient stake.
- **Non-functional Considerations:**
  - Security: Deletion should always be allowed regardless of stake status
  - Performance: Metrics update should not significantly impact deletion performance
  - Observability: Updated metrics reflect current storage requirements
- **Business Rules:**
  - StorageDelete never fails due to insufficient stake
  - min_stake_amount must be recalculated after successful deletion
  - Metrics update happens as part of existing UpdateStorageMetrics call
  - All existing deletion validation and logic remains unchanged
  - Only the metrics calculation includes the new min_stake_amount field

## Design
- **Technical Specifications:**
  - No changes to deletion validation or authorization logic
  - Existing UpdateStorageMetrics call will automatically include min_stake_amount calculation
  - Ensure UpdateStorageMetrics properly calculates new min_stake_amount based on updated total_bytes
  - No additional validation or checks related to staking in deletion flow
- **Architectural Compliance:**
  - Maintains existing deletion semantics and behavior
  - Leverages existing metrics update mechanism
  - No breaking changes to deletion API or behavior

## Testing
- **Test Cases:**
  - Successful deletion updates min_stake_amount correctly
  - Deletion works regardless of owner's current stake status
  - Multiple deletions correctly recalculate min_stake_amount
  - Edge case: deleting all storage results in min_stake_amount = "0"
  - Existing deletion tests continue to pass
- **Test Data Requirements:**
  - Accounts with various storage amounts to delete
  - Different storage_stake_multiple parameter values
  - Scenarios where owner has insufficient stake but can still delete

## Change Plan
- **Files to Modify:**
  - `x/storage/keeper/msg_server.go` - Ensure UpdateStorageMetrics call includes min_stake_amount calculation
  - `x/storage/keeper/keeper.go` - Update UpdateStorageMetrics to calculate min_stake_amount
- **Implementation Approach:**
  1. Verify existing UpdateStorageMetrics call in StorageDelete works with new min_stake_amount field
  2. Update UpdateStorageMetrics method to calculate and store min_stake_amount
  3. Ensure no additional validation or restrictions are added to deletion flow
  4. Add tests to verify min_stake_amount is correctly updated after deletions
  5. Verify existing deletion tests continue to pass without modification

# 19-1 Add storage_stake_multiple parameter to storage module params

[Back to task list](./19-tasks.md) | [View Backlog](../backlog.md#user-content-19)

## Analysis
- **Purpose:** Add a new configurable parameter `storage_stake_multiple` to control stake requirements per byte of storage.
- **Non-functional Considerations:**
  - Security: Parameter must be properly validated to prevent negative values or invalid decimals
  - Performance: Minimal impact as this is a configuration parameter
  - Observability: Parameter changes should be governable and auditable
- **Business Rules:**
  - Default value must be "1.0" (1 udys per byte)
  - Value "0" disables staking requirements entirely
  - Must support decimal precision using cosmos-sdk math.LegacyDec type
  - Must be updateable via governance (MsgUpdateParams)

## Design
- **Technical Specifications:**
  - Add `storage_stake_multiple` field to `Params` message in `proto/dysonprotocol/storage/v1/params.proto`
  - Field type: `string` (to store decimal representation)
  - Add validation logic in `Params.Validate()` method to ensure valid decimal format
  - Update default parameters in keeper initialization
- **Architectural Compliance:**
  - Follows existing pattern of storage module parameters
  - Integrates with existing governance parameter update mechanism
  - Uses cosmos-sdk decimal handling best practices

## Testing
- **Test Cases:**
  - Parameter serialization/deserialization works correctly
  - Default value "1.0" is set properly
  - Validation rejects invalid decimal strings
  - Validation accepts valid decimal strings including "0"
  - UpdateParams governance message works with new parameter
- **Test Data Requirements:**
  - Valid decimal strings: "1.0", "0", "0.5", "1000.123456"
  - Invalid strings: "abc", "", "-1.0", "1.0.0"

## Change Plan
- **Files to Modify:**
  - `proto/dysonprotocol/storage/v1/params.proto` - Add storage_stake_multiple field
  - `x/storage/types/params.go` - Add validation logic and default value
  - `x/storage/keeper/keeper.go` - Set default parameters during initialization
- **Implementation Approach:**
  1. Update protobuf definition with new field
  2. Run `make proto-gen install` to generate Go code
  3. Add validation logic using cosmos-sdk math.LegacyNewDecFromStr
  4. Update default parameters
  5. Add unit tests for parameter validation

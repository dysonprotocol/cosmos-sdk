# 19-6 Implement stake validation in StorageSet operations

[Back to task list](./19-tasks.md) | [View Backlog](../backlog.md#user-content-19)

## Analysis
- **Purpose:** Add stake validation logic to StorageSet to ensure owners have sufficient delegated stake before allowing storage operations.
- **Non-functional Considerations:**
  - Security: Must prevent storage operations when stake is insufficient
  - Performance: Stake validation adds overhead but should be acceptable for write operations
  - Observability: Clear error messages when validation fails
- **Business Rules:**
  - Validation occurs before storage operation (fail fast)
  - Calculate required stake: new_total_bytes × storage_stake_multiple
  - Query owner's current delegated stake using staking module
  - Allow operation if current_stake ≥ required_stake
  - Special case: storage_stake_multiple = "0" disables validation entirely
  - Update metrics after successful storage (existing behaviour)

## Design
- **Technical Specifications:**
  - Add stake validation logic to StorageSet method in msg_server.go
  - Calculate new total bytes after the operation (existing_bytes - old_entry_bytes + new_entry_bytes)
  - Use GetTotalDelegatedStake method to query current stake
  - Use CalculateMinStakeAmount to compute required stake
  - Return ErrInsufficientStake if validation fails
  - Validate before any storage mutations occur
- **Architectural Compliance:**
  - Follows fail-fast validation patterns
  - Integrates with existing StorageSet flow
  - Uses existing helper methods for consistency

## Testing
- **Test Cases:**
  - Successful storage with sufficient stake
  - Rejected storage with insufficient stake
  - Bypass validation when storage_stake_multiple = "0"
  - Edge case: updating existing entry (calculating correct delta)
  - Edge case: zero bytes storage (should always pass)
  - Error handling: staking query failures
  - Error handling: invalid calculation parameters
- **Test Data Requirements:**
  - Test accounts with various delegation amounts
  - Storage entries of different sizes
  - Different storage_stake_multiple parameter values

## Change Plan
- **Files to Modify:**
  - `x/storage/keeper/msg_server.go` - Add stake validation to StorageSet method
- **Implementation Approach:**
  1. Add stake validation logic early in StorageSet method
  2. Calculate projected total bytes after the operation
  3. Query current delegated stake for the owner
  4. Calculate required stake using helper method
  5. Compare and return appropriate error if insufficient
  6. Ensure validation is bypassed when storage_stake_multiple = "0"
  7. Add comprehensive integration tests covering all scenarios

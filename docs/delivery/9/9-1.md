# 9-1 Analyse spec delta & design changes

[Back to task list](./tasks.md) · [View Backlog](../backlog.md#user-content-9)

## Analysis

- **Purpose:** Identify all differences between current `demo-tew/script.py` implementation and spec v0.2, and outline changes required for compliance.
- **Non-functional Considerations:**
  - Security: Ensure signature verification, equivocation proofs, and deterministic execution are covered.
  - Performance: Avoid redundant storage reads; deterministic engine executed only once per round.
  - Observability: We will add verbose error messages; consider future event emission.
- **Business Rules:**
  1. A slot referencing `prev_round_height` implicitly approves that round.
  2. All slots for `round = head + 1` must agree on the preceding snapshot hash.

### Delta Summary

| Area | Current Code | Spec v0.2 Requirement | Change |
|------|--------------|-----------------------|--------|
| Storage prefixes | `l2/latest_round`, `l2/state/...` only | Full key set (§2) including `slots`, `membership`, `evidence` | Add helpers & migrate paths |
| Genesis | N/A (implicit round 0) | `genesis(initial_genesis)` @l1 stores snapshot, core_logic | Implement function & id allocation |
| Membership | Hard-coded authority set | Dynamic committee via join/leave queues | Implement queues & flush logic |
| Slot submission | Inline in progress_round | Separate `submit_slots` @l1 validating ADR-036 | Create new function |
| Approval model | 100 % participation per round | Each slot approves *previous* round; progress requires timeout | Adjust rules, enforce prev_round_hash check |
| Deterministic engine | Inline apply loop | `_next_snapshot` executing `core_logic` | Refactor engine |
| Checkpoint | Missing | `checkpoint` fast-forward with agg-sig | Stub implementation |

## Design

1. **Module layout**
   Keep single `script.py`; introduce helper section mirroring reference script.
2. **ID allocation**
   Implement `_alloc_id()` counter in storage.
3. **Signature verification**
   Use existing `QueryVerifyTx` ABCI query (already available in reference).
4. **Equivocation**
   Compare stored vs new `slot_logic`; on mismatch store `{old,new}` under `evidence/eqv/...` and reject.
5. **Timeout enforcement**
   Require `time.time() >= started_at + timeout` before `progress_round`.
6. **Backward compatibility**
   Old message-board data will be reset by simulator; no migration.

## Testing

- **Unit**: Genesis → submit two rounds; ensure snapshot meta matches; equivocation raises.
- **Integration**: Use updated `simulate.py` to run ≥3 rounds with network loss 0 %.
- **Edge cases**: Timeout not reached, invalid prev_round_hash, duplicate slot submission.

## Change Plan

- **Files to Modify**: `demo-tew/script.py`, `demo-tew/simulate.py`, new tests under `tests/tew/`.
- **Implementation Approach**: Incremental – tasks 9-2 … 9-8 each focus on one area; tests land with 9-9.

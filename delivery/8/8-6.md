# 8-6 End-to-end tests for bidding & listing

[Back to task list](./tasks.md) | [View Backlog](../backlog.md#user-content-8)

## Analysis
- **Purpose:** Ensure the end-to-end experience for bidding and listing NFTs works across supported denoms, and errors are surfaced for unsupported denoms.
- **Non-functional Considerations:** Tests must be deterministic, run in CI, and avoid flakiness by seeding predictable blockchain state.
- **Business Rules:** Only denoms defined in `ParamsAllowedDenoms` can be used for bidding and listing fees.

## Design
- **Technical Specifications:**
  - Tooling: Playwright (preferred) or Cypress if already included.
  - Location: `tests/nameservice/nft_allowed_denoms_param.py`.
  - Scenario matrix:
    1. **Happy paths:**
       - Create a new NFT class with `always_listed=false`
       - Mint an NFT with the new class
       - Set the NFT's valuation to 1000 `dys`
       - Set the NFT's listing status to `listed`
       - Bid with `dys` (allowed) succeeds.
       - Toggle Listing with `dys` succeeds.
    2. **Error paths:**
       - Set the NFT's listing status to `listed` and set the valuation to 1000 `nope` is disallowed
       - Bid with `nope` (disallowed) shows validation error and transaction is rejected.
       - Toggle Listing with disallowed denom shows same error.
    3. **Update Params:**
       - Register a new random name (foo31312.dys) and mint coins with it
       - Update `ParamsAllowedDenoms` to include `dys` and `foo31312.dys`.
       - Setting valuation with 100 `foo31312.dys` succeeds.
       - Bid with 100 `dys` fails. (not the correct denom)
       - Bid with 100 `foo31312.dys` succeeds.
       - Update valuation with 200 `foo31312.dys` succeeds.

## Testing
- **Test Data Requirements:** Pre-seeded NFT class with `always_listed=false`; at least one NFT owned by test wallet.
- **Test Cases:**
  1. Attempt bid with allowed denom using CLI → Transaction succeeds; bid is recorded on-chain.
  2. Attempt bid with disallowed denom using CLI → CLI returns error; no transaction is broadcast.
  3. Toggle listing with allowed denom using CLI → Listing state is updated; state persists after querying again.
  4. Toggle listing with disallowed denom using CLI → CLI returns error; listing state remains unchanged.

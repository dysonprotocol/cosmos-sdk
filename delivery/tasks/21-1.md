# 21-1 Implement link_page and unlink_page functions

[Back to task list](./21-tasks.md) | [View Backlog](../backlog.md#user-content-21)

## Analysis
- **Purpose:** Implement core functions for linking and unlinking custom author pages that validate author authority and store page references
- **Non-functional Considerations:**
  - Security: Must validate author is signer or destination of name service before allowing operations
  - Performance: Use existing storage patterns for efficient data access
  - Observability: Follow existing error handling patterns with descriptive messages
- **Business Rules:** Only authorized authors can create/remove their own custom page links

## Design
- **Technical Specifications:**
  - `link_page(author, path, title, post_id)` function in `nuance/script.py`
  - `unlink_page(author, path)` function in `nuance/script.py`
  - Storage pattern: `author_page/<author>/<path>` containing `{"title": title, "post_id": post_id}`
  - Author validation using existing nameservice resolution pattern
- **Architectural Compliance:** Follows existing patterns from `edit_author_profile` and `publish_post` functions

## Testing
- **Test Cases:**
  - Authorized author can link/unlink pages
  - Unauthorized users cannot modify pages
  - Invalid post_ids are rejected
  - Duplicate paths are handled appropriately
- **Test Data Requirements:** Test accounts, valid post_ids, various path strings

## Change Plan
- **Files to Modify:**
  - `nuance/script.py` (add link_page and unlink_page functions)
- **Implementation Approach:**
  1. Add link_page function with author validation and storage
  2. Add unlink_page function with author validation
  3. Add helper functions for author page storage paths
  4. Test functions via CLI to ensure proper validation

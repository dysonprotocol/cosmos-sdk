# 22-1 Analyze requirements and design reverse mapping storage

[Back to task list](./22-tasks.md)  
[View Backlog](../backlog.md#user-content-22)

## Analysis
- **Purpose:** Design storage and logic for reverse mappings from addresses to names in Nameservice module.
- **Non-functional Considerations:**
  - Security: Ensure mappings only accessible via queries, updates restricted to authorized methods.
  - Performance: Efficient storage for potentially many names per address; use indexed collections.
  - Observability: Emit events on mapping updates.
- **Business Rules:** Mappings update on destination changes only (not transfers).

## Design
- **Technical Specifications:** Add `collections.Map[collections.Pair[string,string], string]` where index is (destination, source) and value is source name. Query uses prefix on destination for efficient lookup.
- **Architectural Compliance:** Follow Cosmos SDK collection patterns, standard gRPC query with pagination.

## Testing
- **Test Cases:** Verify design covers updates, queries, pagination. Add CLI tests.
- **Test Data Requirements:** Sample names and addresses for comprehensive testing.

## Change Plan
- **Files to Modify:** x/nameservice/keeper/keeper.go, types/keys.go, proto/query.proto
- **Implementation Approach:** Define new collection with Pair keys, update SetDestination method, add proto definition and CLI commands.
- **Build Requirements:** Use "make proto-gen" to regenerate Go types after proto changes.
- **Testing:** Add tests to ./tests/ and test with "make test PYTEST_ARGS=/tests/... -x --ff".

## Analysis
- **Purpose:** Implement storage for reverse mappings using efficient key structure.
- **Non-functional Considerations:**
  - Security: Access controls.
  - Performance: Efficient iteration using prefix queries.
- **Business Rules:** Index structure: (destination, source) -> source for efficient lookups.

## Design
- **Technical Specifications:** Use `collections.Map[collections.Pair[string,string], string]` where key is (destination_address, source_name) and value is source_name.
- **Architectural Compliance:** SDK standards for collections with compound keys.

## Testing
- **Test Cases:** Set/get mappings, prefix iteration.
- **Test Data Requirements:** Test addresses/names for compound key testing.

## Change Plan
- **Files to Modify:** keeper/keeper.go
- **Implementation Approach:** Add to schema and keeper with proper key structure for prefix queries.

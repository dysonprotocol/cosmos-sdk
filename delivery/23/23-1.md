# 23-1 Add MsgCreateExternalName to tx.proto

[Back to task list](./23-tasks.md)  
[View Backlog](../backlog.md#user-content-23)

## Analysis
- **Purpose:** Add new message type to allow nameservice authority to create names directly without commit-reveal process
- **Non-functional Considerations:**
  - Security: Authority-only access prevents unauthorized name creation
  - Performance: Direct creation bypasses commit-reveal overhead
  - Observability: Standard protobuf message with proper annotations
- **Business Rules:**
  - Only nameservice authority can sign this message
  - Name must follow domain/subdomain format
  - No .dys suffix requirement unlike regular names

## Design
- **Technical Specifications:**
  - Add MsgCreateExternalName and MsgCreateExternalNameResponse to tx.proto
  - Authority signer field with cosmos.AddressString annotation
  - Name field for the external name to create
  - Standard cosmos.msg.v1.signer annotation for authority field
- **Architectural Compliance:**
  - Follows existing nameservice message patterns
  - Uses standard Cosmos SDK message structure
  - Consistent with authority-based operations

## Testing
- **Test Cases:**
  - Message structure validates correctly
  - Protobuf generation succeeds
  - Generated Go types are available
- **Test Data Requirements:**
  - Valid authority address
  - Valid domain names (e.g., "example.com", "sub.domain.org")

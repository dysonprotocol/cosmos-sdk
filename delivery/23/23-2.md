# 23-2 Add ExternalNameRegex validation

[Back to task list](./23-tasks.md)  
[View Backlog](../backlog.md#user-content-23)

## Analysis
- **Purpose:** Create regex validation for external names following domain/subdomain format
- **Non-functional Considerations:**
  - Security: Prevents injection of invalid characters in names
  - Performance: Compiled regex for efficient validation
  - Observability: Clear validation error messages
- **Business Rules:**
  - Domain format: lowercase alphanumeric with dashes
  - Must contain at least one dot (domain.tld minimum)
  - No .dys suffix restriction unlike NameRegex
  - Follow standard domain name rules

## Design
- **Technical Specifications:**
  - Add ExternalNameRegex constant alongside existing NameRegex
  - Pattern: `^[a-z0-9]([-a-z0-9]*[a-z0-9])?(\.[a-z0-9]([-a-z0-9]*[a-z0-9])?)+$`
  - Export regex for use in validation functions
- **Architectural Compliance:**
  - Follows existing NameRegex pattern in nameservice types
  - Consistent with Cosmos SDK validation patterns
  - Reusable across different message handlers

## Testing
- **Test Cases:**
  - Valid domains: "example.com", "sub.domain.org", "a.b"
  - Invalid domains: "example", ".com", "example.", "-example.com"
  - Edge cases: single letters, maximum length domains
- **Test Data Requirements:**
  - Comprehensive test cases for regex validation
  - Both positive and negative test scenarios

## Change Plan
- **Files to Modify:**
  - Look for existing NameRegex definition (likely in types package)
  - Add ExternalNameRegex alongside it
- **Implementation Approach:**
  - Add compiled regex constant
  - Follow same pattern as existing NameRegex
  - Include validation helper if needed

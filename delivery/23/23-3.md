[Back to task list](./23-tasks.md)

## Analysis
- **Purpose:** Implement message handler for direct external name creation bypassing commit-reveal
- **Non-functional Considerations:**
  - Security: Validate authority permissions before name creation
  - Performance: Direct NFT creation without commitment overhead
  - Observability: Emit events for external name registration
- **Business Rules:**
  - Only nameservice authority can execute this message
  - Name must pass ExternalNameRegex validation
  - Create NFT directly with authority as owner
  - No valuation or fee requirements

## Design
- **Technical Specifications:**
  - Add CreateExternalName method to Keeper with MsgServer interface
  - Validate authority matches module authority (typically gov module)
  - Validate name format using ExternalNameRegex
  - Create NFT with Names class ID directly
  - Set basic NFT data without valuation
- **Architectural Compliance:**
  - Follow existing message handler patterns in nameservice
  - Use same NFT creation flow as Reveal handler
  - Consistent error handling and event emission

## Testing
- **Test Cases:**
  - Authority validation (valid/invalid authority addresses)
  - Name format validation using ExternalNameRegex
  - NFT creation and ownership verification
  - Event emission verification
- **Test Data Requirements:**
  - Valid authority address (module authority)
  - Valid external domain names
  - Invalid authority addresses for negative testing

## Change Plan
- **Files to Modify:**
  - Create new file: `x/nameservice/keeper/msg_create_external_name.go`
  - Update: `x/nameservice/keeper/msg_server.go` (if needed for interface)
- **Implementation Approach:**
  - Follow pattern from msg_reveal_name_registration.go
  - Remove commit-reveal logic, valuation, and fees
  - Add authority validation
  - Use ExternalNameRegex instead of NameRegex
  - Emit appropriate events for external name creation

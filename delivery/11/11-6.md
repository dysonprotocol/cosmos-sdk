# 11-6 Create wrapper methods for safe queue access

[Back to task list](./tasks.md) · [View Backlog](../backlog.md#user-content-11)

## Analysis

- **Purpose:** Implement validated wrapper functions to allow chain_logic to interact with queues safely, providing controlled access to queue operations.
- **Non-functional Considerations:**
  - Security: Wrapper methods must validate all inputs and prevent malicious queue operations
  - Performance: Wrappers should add minimal overhead to queue operations
  - Observability: Wrapper method calls and validation failures should be logged
- **Business Rules:**
  1. User transaction code can only access queues through validated wrapper functions exposed in chain_logic
  2. Wrapper functions validate message content, size limits, and format (e.g., greeting text max 100 chars)
  3. Direct queue access from user transaction code is prohibited
  4. Chain_logic exposes application-specific wrapper functions like `send_greeting_to_l1`

## Design

- **Technical Specifications:**
  - Queue wrapper methods are exposed through chain_logic.py in the `on_tx` function:
    ```python
    def on_tx(msg):
        # Extract the Python code from the tx data and execute it
        code = msg["data"].get("data", "")
        if code.strip():
            # Create wrapper functions for queue operations
            def send_greeting_to_l1(greeting_text):
                """Send greeting message to L1 with validation"""
                if not isinstance(greeting_text, str):
                    raise ValueError("Greeting must be a string")
                if len(greeting_text) > 100:
                    raise ValueError("Greeting too long (max 100 characters)")
                return tew.send_l1_message({"type": "greeting", "content": greeting_text})
            
            def send_greeting_to_l2(greeting_text):
                """Send greeting message to L2 with validation"""
                if not isinstance(greeting_text, str):
                    raise ValueError("Greeting must be a string")
                if len(greeting_text) > 100:
                    raise ValueError("Greeting too long (max 100 characters)")
                return tew.send_l2_message({"type": "greeting", "content": greeting_text})
            
            eval_scope = {
                "print": _print,
                "send_greeting_to_l1": send_greeting_to_l1,
                "send_greeting_to_l2": send_greeting_to_l2,
                "tew": tew_module_with_queues  # Extended tew module
            }
            result = dys_eval(code, scope=eval_scope)
    ```
  - Implement core queue functions in tew_module:
    ```python
    def _send_l1_message(message_data):
        """Core L1 message sending with validation"""
        if not isinstance(message_data, dict):
            raise ValueError("Message data must be a dictionary")
        if len(json.dumps(message_data)) > 1000:  # Size limit
            raise ValueError("Message too large (max 1000 bytes)")
        
        # Get L1 queue from chain scope
        l1_queue = chain_scope.get("l1_queue")
        if l1_queue:
            return l1_queue.send_message(message_data)
        raise ValueError("L1 queue not available")
    
    tew_module_with_queues = {
        "create_account": create_account_wrapper,
        "send_l1_message": _send_l1_message,
        "send_l2_message": _send_l2_message,
    }
    ```

- **Architectural Compliance:**
  - Follows TewChain pattern of providing safe functions through tew_module
  - Maintains queue operation semantics while adding validation layer
  - Enables controlled queue access for chain_logic implementations

## Addendum: Architecture Simplification (2025-01-02)

The implementation has evolved from the original design. The chain_logic layer has been removed, and wrapper functions are now implemented directly in the script:

### Key Changes:
1. **No chain_logic.py**: Wrapper functions are no longer in a separate chain_logic file
2. **Direct implementation**: Safe wrapper functions are created in `on_tx_wrapper()` within `queue_chain.py`
3. **Simplified sandbox**: TEW transactions have a minimal sandbox with only necessary functions
4. **Stricter validation**: Wrapper functions now have tighter constraints (e.g., 20 char limit instead of 100)

### Updated Implementation:
```python
# In queue_chain.py on_tx_wrapper()
def safe_send_l1_message(text):
    """Safe wrapper for sending L1 messages from transactions
    
    Accepts only strings under 20 characters and automatically sets the sender.
    """
    if not isinstance(text, str):
        raise ValueError("Message must be a string")
    if len(text) >= 20:
        raise ValueError("Message too long (max 19 characters)")
    # Automatically create message dict with sender
    message_dict = {"sender": msg["signer"], "text": text}
    return _send_l1_message(message_dict)

# Minimal sandbox for TEW transactions
tx_eval_scope = {
    "print": tx_print,
    "signer": msg["signer"],
    "send_l1_message": safe_send_l1_message,
    "send_l2_message": safe_send_l2_message,
    "query_dyson": safe_query_dyson,
}
```

### Updated Process:
- **Before**: User Code → chain_logic wrappers → tew_module → queue operations
- **After**: User Code → safe wrappers in on_tx_wrapper → internal queue operations

The security model remains the same - user transactions can only access queues through validated wrapper functions. The implementation is now more direct and consolidated within the main script.

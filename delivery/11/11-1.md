# 11-1 Analyse integration requirements & design merged system

[Back to task list](./tasks.md) · [View Backlog](../backlog.md#user-content-11)

## Analysis

- **Purpose:** Document architecture for merging TewQueue and TewChain into a unified system that enables L1↔L2 queue communication within blockchain transactions.
- **Non-functional Considerations:**
  - Security: Queue operations must not compromise transaction validation or block integrity
  - Performance: Queue processing should be minimal overhead during block processing
  - Observability: Queue message failures should be logged without failing transactions
- **Business Rules:**
  1. Queue state is part of TewChain block state, stored in `post_state` with namespaced keys
  2. Queue processing happens automatically during `on_begin_block` before transaction execution
  3. Chain_logic can access queues only through validated wrapper methods
  4. Queue operation failures are logged but do not fail the transaction

## Design

- **Technical Specifications:**
  - Merge `queue.py` and `chain.py` into single `demo-tew/queue_chain.py` module
  - Extend `StateDict` TypedDict to include queue state fields:
    ```python
    class QueueStateDict(StateDict):
        # L1 queue state (persisted to DysonProtocol storage)
        l1_queue_state: Optional[Dict[str, Any]]
        # L2 queue state (persisted in block state)  
        l2_queue_state: Optional[Dict[str, Any]]
    ```
  - Queue storage keys abstracted into L1/L2 classes: `_get_storage_key(instance_id)`
  - Chain_logic callbacks extended:
    ```python
    chain_callbacks = {
        "on_begin_block": ...,
        "on_tx": ..., 
        "on_end_block": ...,
        "on_queue_message": ...,  # Process incoming queue message
        "on_queue_response": ..., # Process queue response/acknowledgment
    }
    ```

- **Architectural Compliance:**
  - Follows TewProtocol v0.6 storage schema for chain state
  - Maintains TewQueue message passing semantics
  - Preserves dyslang compatibility requirements

## Addendum: Architecture Simplification (2025-01-02)

The implementation has evolved from the original design. The chain_logic layer has been removed, simplifying the architecture:

### Key Changes:
1. **No chain_logic separation**: All L1 and L2 logic is now directly implemented within the DysonProtocol script (`queue_chain.py`)
2. **No core_logic.py source code**: There is no separate chain_logic code to be stored in the TewBlock state
3. **Direct implementation**: The callbacks (`on_queue_message`, `on_queue_response`) mentioned in the original design are now methods of the L1 and L2 classes within the script
4. **Sample chain_logic removed**: The sample `demo-tew/chain_logic_with_queue.py` is no longer needed as logic is integrated into the main script

### Implications:
- The QueueStateDict still exists but without the `chain_logic` field
- TEW transactions run in a minimal sandbox with access to safe wrapper functions only
- The validation and wrapper function patterns remain but are implemented directly in `queue_chain.py`
